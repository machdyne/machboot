# The RP2040 supervisor (Sergei, Mozart)

Sergei and Mozart carry an RP2040 next to the Sechzig module. As
shipped it runs a fork of pico-dirtyJtag: JTAG for openFPGALoader, and
the module's UART as a USB serial port. machboot replaces that firmware
with its own, the **supervisor**, which does the same and more:

- **The same as before:** dirtyJTAG-compatible JTAG, the UART on USB,
  the module's 48 MHz clock. openFPGALoader and a terminal cannot tell
  the difference, and a PC using JTAG always takes priority.
- **The menu at power-on:** it loads machboot into the FPGA's SRAM over
  JTAG at power-on and after every reset (docs/power-on.md).
- **The list of systems:** it keeps systems in its flash and loads them
  over JTAG when machboot asks (docs/systems.md).
- **Settings and the card reader**, over the XA-XD link to machboot
  (docs/xlink.md).

**Files:** `machboot-sv.uf2` is the supervisor alone;
`machboot-<carrier>_ml<n>.uf2` (Sergei or Mozart, ML0/ML1/ML2) adds the
menu for that module, which the RP2040 then loads at power-on
(docs/power-on.md).

Clean-room: written from the dirtyJTAG protocol as its hosts use it
(openFPGALoader's cable driver is the reference for what goes over the
wire), from the RP2040 datasheet and pico-sdk, and from the carriers'
schematics. No dirtyJTAG firmware code. Only its USB IDs and its version
string are taken, because hosts look for them.

## Installing it, and going back

```
hold BOOT, apply power      -> a drive called RPI-RP2
copy machboot-sv.uf2 to it  -> the RP2040 restarts with it
```

To go back, copy the board's original `dirtyJtag.uf2` (in the
`sergei` and `mozart` repos, `firmware/`) the same way. The RP2040's
boot ROM does this, so no firmware can break it.

The firmware can also restart into the boot ROM by itself, without the
button: send it `CMD_GOTOBOOTLOADER` (0x08) on the JTAG interface.

## The pins

From the schematics (`sergei/pcb/v0/ld5.kicad_sch`,
`mozart/pcb/mozart.kicad_sch`); the two carriers are the same:

| RP2040 | Net | Use |
|---|---|---|
| GP4 | UART_RX | UART1 TX, to the module's UART input |
| GP5 | UART_TX | UART1 RX, from the module's UART output |
| GP8, GP9, GP10, GP11 | XC, XD, XB, XA | the XA-XD link (docs/xlink.md): SPI1 RX (MISO), CS, SCK, TX (MOSI); released unless machboot answers |
| GP12 | LED_R | active low. On: a PC has configured the USB port; blinks with JTAG activity |
| GP16 | JTAG_TDI | |
| GP17 | JTAG_TDO | input, pulled up |
| GP18 | JTAG_TCK | |
| GP19 | JTAG_TMS | |
| GP20 | SYS_RST_N | never driven: an input with the pull-up on (the pad's reset default is a pull-down), watched for resets |
| GP23 | SYS_CLK48 | **GPOUT1, 48 MHz from clk_usb: the module's clock** |

**The clock comes first.** The module has no oscillator of its own for
`SYS_CLK48`. The firmware starts GPOUT1 as the first thing in `main()`,
before USB or anything else, and never stops it.

## What the PC sees

```
1209:C0CA  Machdyne "machboot supervisor"   (the same IDs as dirtyJTAG)
  interface 0    vendor: JTAG, bulk OUT 0x01, bulk IN 0x82
  interface 1+2  CDC-ACM: the module's UART  (/dev/ttyACM0)
  interface 3    mass storage: the card reader, "Machdyne SD card reader" (docs/xlink.md)
```

openFPGALoader opens the device by those IDs and claims interface 0, so
`openFPGALoader -c dirtyJtag ...` works unchanged:

```
openFPGALoader -c dirtyJtag --detect
openFPGALoader -c dirtyJtag image.bit           (SRAM)
openFPGALoader -c dirtyJtag -f image.bit        (the module's flash)
```

The serial port takes its baud rate from the terminal (default 115200):
`minicom -D /dev/ttyACM0 -b 115200`.

## The protocol (dirtyJTAG version 2)

The JTAG interface's bulk OUT data is one stream of commands. A command
and its data may straddle USB packets.

| Byte | Command | Arguments | Reply |
|---|---|---|---|
| 0x00 | STOP | | (replies so far go out) |
| 0x01 | INFO | | `DJTAG2\n` |
| 0x02 | FREQ | kHz, 2 bytes, big-endian | |
| 0x03 | XFER | bit count (1 byte; +256 with flag 0x40); the bits, MSB of each byte first | the TDO bits, same layout, unless flag 0x80 (NO_READ) |
| 0x04 | SETSIG | mask, value: TCK 0x02, TDI 0x04, TMS 0x10, TRST 0x20, SRST 0x40 | |
| 0x05 | GETSIG | | one byte: the outputs, and TDO as 0x08 |
| 0x06 | CLK | signals (TMS, TDI), count | |
| 0x08 | GOTOBOOTLOADER | | (the RP2040 restarts into its boot ROM) |

XFER keeps TMS as it was. TDI changes while TCK is low, and TDO is read
just before TCK rises (the target changes it on the falling edge).
Version 2 allows up to 511 bits per XFER; openFPGALoader sends 496.

## Speed

The supervisor drives the pins from the CPU, through the SIO. Each bit is a
few instructions, so TCK tops out around 10 MHz, and USB round trips
dominate for small shifts. The supervisor's own loads run at 6 MHz; on
a Sergei ML2 the menu (434 KB) loads in about 1.1 s. A PIO engine is the
planned speed-up.

## Building

```
make sv PICO_SDK_PATH=/path/to/pico-sdk      -> build/machboot-sv.uf2
```

This needs pico-sdk 1.5.x with `lib/tinyusb`
(`git submodule update --init lib/tinyusb`), an arm-none-eabi GCC, and
cmake. A prebuilt `machboot-sv.uf2` is in the binaries zip.

```
rp2040/
  CMakeLists.txt
  src/board.h           the pins
  src/main.c            the clock, the USB tasks, the UART bridge, the LED
  src/djtag.c/.h        the protocol (portable)
  src/jtag_io.h         the pin interface djtag.c uses
  src/jtag_rp2040.c     ... on the RP2040
  src/usb_descriptors.c
  src/tusb_config.h
  src/xlink.c/.h        the XA-XD link, the master's side (portable)
  src/xlink_io.h        its pins ... 
  src/xlink_rp2040.c    ... on the RP2040: SPI1, 6.25 MHz
  src/msc.c/.h          the card reader's logic (portable)
  src/msc_tusb.c        its TinyUSB callbacks
  tests/test_xlink.c    the card reader on a PC, against fw/xlink.c
  tests/test_djtag.c    the protocol on a PC, against a JTAG TAP model
```

## Tested

`make sv-test` (part of `make test`) runs `src/djtag.c` on a PC against
a JTAG TAP model: the IEEE 1149.1 state machine, an ECP5's 8-bit IR
(READ_ID), a 64-bit register and a burst sink. A host side sends what
openFPGALoader's dirtyJtag driver sends, in 64-byte packets:

- INFO, then FREQ;
- TMS moves as SETSIG pairs: Test-Logic-Reset, Run-Test/Idle, Shift-IR;
- the IR capture reads 0x01;
- **the IDCODE (0x41111043) read** through XFER, with the last bit by
  SETSIG/GETSIG;
- a 64-bit register written with NO_READ and read back;
- 32,768 bits of burst through XFERs with EXTEND_LENGTH, byte for byte;
- CLK runs in Run-Test/Idle;
- an XFER whose header ends one USB packet and whose length begins the
  next;
- GOTOBOOTLOADER.

`make sv-test` also runs `tests/test_xlink.c`: the card reader's
`src/xlink.c` and `src/msc.c` against the FPGA firmware's own
`fw/xlink.c`, through a byte-level model of the gateware's link
(docs/xlink.md, "Tested"); and the gate-level simulation (`sim-xl`) runs
the same two files against the real RTL.

It also runs `tests/test_sv.c` (the power-on menu) and
`tests/test_systems.c` (the system cache: `src/cache.c` and the requests
in `src/msc.c`, docs/systems.md). Both put the RP2040's flash in RAM and
an ECP5 model on the JTAG pins.

On the board, the first things to try after copying a UF2:

1. Copy `machboot-sv.uf2`. The LED comes on when the PC has set the
   port up, and the module runs (its clock is there).
2. `openFPGALoader -c dirtyJtag --detect`: the module's FPGA.
3. `openFPGALoader -c dirtyJtag image.bit`: an SRAM load. Then the
   serial port: the image's console.
4. `-f` to the module's flash, and a power cycle.
5. If anything fails: the original `dirtyJtag.uf2` brings it back.
