# Provenance

## Clean-room statement

machboot contains **no code from tinydfu-bootloader** (or from the
TinyFPGA bootloader and the USB cores it derives from), and its RP2040
firmware contains none from pico-dirtyJtag. Where machboot
does what those do, it is written from the published specifications and
datasheets:

| Area | Written from |
|---|---|
| DVI output (`rtl/mb_tmds.v`, `rtl/mb_dvi.v`) | DVI 1.0 specification: section 3.2 (TMDS encoding), 3.3.3 (control tokens) |
| Video timing (`rtl/mb_text.v`) | VESA DMT, 640x480 at 60 Hz |
| Bitstream inspection (`fw/flash.c`) | Lattice TN1260 (ECP5 sysCONFIG): bitstream format, preamble, VERIFY_ID |
| SD card (`fw/sd.c`, `tests/sdmodel.c`) | SD Physical Layer Simplified Specification, chapter 7 (SPI mode) |
| FAT (`fw/fat.c`) | Microsoft, "FAT: General Overview of On-Disk Format" (fatgen103); the PC MBR partition table |
| USB keyboards (`fw/usb.c`, the model in `fw/host/hw_host.c`) | USB 2.0 chapter 9, HID 1.11 (boot interface); the controller's programming model and its rules from Zeitlos `docs/usb_host.md` and `sw/apps/usb/usbh.c` |
| Reconfiguration (PROGRAMN, boot address) | Lattice TN1260; the mechanism as described in Zeitlos `docs/zboot.md` |
| PLL (`rtl/mb_pll.v`) | generated by `ecppll` (Project Trellis) |
| USB device: endpoint buffers (`rtl/mb_usbd.v`), descriptors, chapter 9, CDC, DFU (`fw/usbd.c`), the register model (`fw/host/usbd_host.c`) | USB 2.0 chapters 8 and 9; CDC 1.2 and PSTN 1.2 (ACM); DFU 1.1. The SIE's interface from its own header comments (below) |
| The USB host at the wire in `sim/usbhost.inc` | USB 2.0 chapters 7 and 8 (NRZI, bit stuffing, SYNC/EOP, CRC5/CRC16), independent of the SIE |
| Install mode (`fw/selfinst.c`, `tools/mkinstaller.py`) | machboot's own design (docs/install-mode.md) |
| The DVI receiver model in `sim/` | DVI 1.0 specification (decoding) |

The interface's behaviour is machboot's own design.

|---|---|

## Third-party, via Zeitlos

| Here | Zeitlos | What | License |
|---|---|---|---|
| `rtl/ulixxe/sie.v`, `phy_rx.v`, `phy_tx.v` | `rtl/ext/usb_cdc/` (`d4e6992`) | ulixxe's USB full-speed device SIE and PHY, unchanged | MIT, `rtl/ulixxe/LICENSE` |

The rest of ulixxe's usb_cdc (its CDC control endpoint and FIFOs) is not
used: machboot's endpoint block and firmware stack replace them. It is
not tinydfu's USB core and does not derive from it.

Not used: the rest of Zeitlos's `rtl/ext/` (third-party cores), `rtl/gpu/gpu_ddmi.v`
(third-party DVI code) -- machboot has its own DVI output for that
reason -- and Zeitlos's SD and FAT code (`sdmm.c`, FatFs: ChaN's) --
machboot has its own, read-only and much smaller.

The test cards are made with **pyfatfs** (`pip install pyfatfs`), an
independent FAT implementation, so `fw/fat.c` is checked against someone
else's FAT rather than its own. It is a test tool only.

When a reused file changes in Zeitlos, copy it again and note the
commit here.
